# 急厕雷达 · AI 使用复盘

> 完整工程版见项目仓库 `LEARNING.md`。这里只记"用 AI 的过程"。

## 背景
参加 WorkBuddy 旅行应用大赛，用 AI（Hy3）从 0 做出一个单文件"旅行找厕所"应用并上线。

## AI 使用策略（有效）
- **分阶段**：思路 → 原型 → 迭代，不让 AI 一次堆完。
- **第三方 SDK 先查证**：腾讯地图 API 用法让 AI 先 `WebSearch` 核实，避免凭记忆写错。
- **要验证闭环**：让 AI 写 Node 回归测试（mock 浏览器 / TMap），31 项断言全过才信。

## 关键卡点（AI 给的代码不对，靠查证 + 测试发现）
- 标记不显示：AI 用了 `DOMOverlay`，真机不解析；查文档改 `MultiMarker`。
- 定位飘上万度：坐标转换公式 AI 写错；重写为正确 GCJ-02。
- 导航跳窗：改成页内 `MultiPolyline` 路线。

## 反思
- AI 的第三方 SDK 用法可能是错的，必须自己核实。
- 没有测试 = 盲信；这次测试脚手架是快速定位 bug 的关键。
- 用户的长期约定（"改好直接发"）要写进 memory。

## 产出
可部署的单文件应用 + 回归测试 + 可复用经验。
