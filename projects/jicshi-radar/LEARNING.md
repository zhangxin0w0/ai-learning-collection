# 急厕雷达 · AI 辅助开发学习记录

> 一份"怎么用 AI 把这个项目从 0 做到上线"的真实复盘。重点不是代码，是**过程、判断与验证**。

## 一、背景与目标

- 参加 WorkBuddy「旅行应用创作大赛」，选题"旅行中找厕所"这个刚需小场景。
- 目标：用 AI（WorkBuddy / Hy3）全程辅助，产出一个**单文件 HTML** 应用，能真实部署、真能用。
- 顺带练两件事：① 第三方地图 SDK（腾讯地图 GL JS）的真实集成；② 让 AI 产出"可验证"的代码，而不是"看起来对"。

## 二、AI 工具与关键 prompt 策略

- **分阶段推进**：先确认思路方向 → 出原型 v1 → 迭代进阶版。不让 AI 一次把功能堆完，每轮聚焦。
- **第三方 API 不凭印象**：凡涉及腾讯地图 GL JS 的用法（自定义标记、路线、控件），先让 AI `WebSearch` 核实官方写法，再写。这一步直接避免了"凭记忆写错 SDK"的返工。
- **验证闭环**：要求 AI 写 Node 回归测试——`_extract.js` 从 HTML 抽真实脚本，`_test.js` 用 `vm` 加载并 mock 浏览器 / TMap，对坐标转换、厕所判定、范围过滤、标记生成、路线绘制逐项断言。**AI 给的代码过了测试才信**。

## 三、关键卡点 & 怎么破（附验证）

1. **地图标记完全不显示**
   - 误用 `TMap.DOMOverlay`（依赖 `getProjection()`，真机不解析，标记卡在 0,0 被裁掉）。
   - 查官方文档后改成 `TMap.MultiMarker` + `MarkerStyle`（SVG data-URI 图标）。
   - 验证：`_test.js` 断言标记层正确创建、厕所+用户点 ≥3 个。
2. **定位偏差上万度**
   - `wgs84togcj02` 坐标转换公式写错（漏除椭球半径项），偏移量高达数千度。
   - 重写为正确的 GCJ-02 偏移公式 + 中国境外守卫。
   - 验证：单测偏移回落到 ~0–0.01°（几百米量级，合理）。
3. **导航跳新窗口**
   - 原 `window.open` 打开腾讯 URI 路线页。改成页内 `TMap.MultiPolyline` 画步行路线 + `fitBounds` 自动适配。
   - 验证：测试确认路线层创建、压缩 polyline 解码正确。
4. **整段脚本语法错误导致全失效**
   - `clearMarkers()` 缺一个 `}`，整个 `<script>` 无法解析，所有交互失效。
   - 用自写括号平衡扫描器（尊重字符串/模板/注释）定位到具体行，补上闭合。
5. **地图变长条 + 控件压在顶层**
   - `#tencentMap` 用 `height:100%` 在 flex 父级下解析失败，容器塌成 0 → 长条、标记被压扁。
   - 改绝对铺满（`inset:0`）+ 初始化后 `map.resize()`；关掉腾讯自带缩放/旋转控件，换成自定义按钮。
6. **实时搜索需配 Key 授权域名（外部卡点）**
   - 腾讯 key 需在控制台启用 WebServiceAPI，并把**精确域名**加入授权域名，否则返回 110 拒绝、自动降级回示例点。
   - 这是平台配置，代码绕不过；已在 App 设置面板内自动提示要加的精确域名。

## 四、踩坑 / 反思（最值钱的部分）

- **AI 给的第三方 SDK 用法可能是错的**：必须自己 `WebSearch` 核实再落地。这次就因为先入为主用了 `DOMOverlay` 返工一次。
- **没有验证闭环 = 盲信**：坐标转换 bug 若没单测，上线后用户只会说"定位飘了"，极难排查。测试脚手架（31 项断言）是这次能快速定位、修复的根本原因。
- **用户的"约定"要写进记忆**：用户明确要求"以后每次改好直接发布，不再问"。这类长期约定应记入项目 memory，避免每次重复确认。
- **真实 key 调试 vs 离线降级**：设计上要区分"有 key 真实数据"和"无 key 示例数据"，示例默认隐藏，不污染真实结果展示。

## 五、产出价值

- 一个能真实部署、真能找附近厕所的单文件应用（已上线 WorkBuddy 静态站点）。
- 一套可复跑的回归测试（mock 浏览器 / TMap）。
- 一份"用 AI 做地图集成应用"的可复用经验。
